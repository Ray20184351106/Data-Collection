# 共享目录更新器实施计划

**目标：** 发布一次，设备下次通过更新器启动时升级；设备继续在原目录本地运行。
**设计：** 见 `docs/shared-folder-updater.md`。独立 net462 更新器读取共享目录 latest.json，将全量程序包缓存、解压后更新程序文件。配置、数据库、模型代码、日志不参与替换。
**实施方式：** 用户已批准聊天中的方案并要求连续修改至需要现场指导。本次在现有目录最小修改，保留已有五处未提交工作，不提交、不发布到真实共享目录。

## 全局约束

- 不修改采集、解析、入库逻辑，不连接业务数据库。
- 更新器只有 Framework 自带依赖；已运行的采集程序先正常退出。
- 发布版本独立记录在 installed-version.txt，避免变更既有程序集绑定版本。
- 当前 Debug 程序在运行；构建/验收采用独立输出目录。
- 不递归删除目录，不清空安装目录；按包中明确的程序文件更新。

## 步骤与验证

- [x] 1. 更新引擎：先写真实 ZIP/文件测试，覆盖升级、同版/旧版、离线、现场数据保留、子目录依赖和替换失败；观察失败后实现。
- [x] 2. 启动接入：先验证启动路径选择；登录启动优先 Updater.exe，无更新器保持原行为；配置重启走正常退出并等待旧进程结束。
- [x] 3. 发布/接入脚本：从独立构建输出生成程序包、latest.json 和首次接入工具；先完成包再发布版本信息。
- [x] 4. 验证：更新器全套测试、受影响且不写数据库的 WinForms 测试、隔离构建、实际组包和两版本闭环；检查发布包不含现场配置或数据。
- [x] 5. 复核改动和临时文件，交付代码、操作文档及本地可用接入包；真实共享路径和现场首台验收留给用户。

## 风险与决定

- 文件替换失败需要恢复已替换的程序文件，避免启动半套版本；只对本次更新涉及的文件进行备份恢复。
- 运行数据目录排除和 ZIP 路径解析属于已批准的“仅更新程序文件”范围；不增加采集业务校验。
- 真正共享目录的账号权限、Windows 登录启动、现场采集恢复只能现场验收。
